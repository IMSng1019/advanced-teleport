# Advanced Teleport Implementation Plan

**Goal:** Build a Fabric 1.20.4 client/server mod enforcing infrastructure-dependent player teleportation, with SQLite world storage and a protected registration API.

**Architecture:** Pure Java geometry and graph algorithms are shared by client and server. Clients detect local road changes and compute teleport proposals; the server independently checks actual blocks and graph decisions before committing changes or moving players. World data is authoritative on the server and cached on clients.

**Tech Stack:** Java 17 bytecode, Fabric Loader/API, Yarn 1.20.4, SQLite JDBC, Gson, JUnit 5.

## Decisions

- Data root is the parent of the installed jar's `mods` directory plus `advanced_teleport`; development uses Fabric gameDir. Each world uses a sanitized endpoint + world name directory, with collision-resistant suffixes. Server config is `advanced_teleport/config.json`.
- Cities are dimension-specific closed X/Z polygons. Roads are 3D polylines; stations lie on a registered road. Cities do not connect merely by overlap. Road intersections/proximity, city/road intersections, and actual paired portals establish transitive connectivity.
- Default mode projects a target onto the reachable geometry in its dimension. Strict mode requires a nearby registered station and chooses a station in the source component nearest to the destination component. Off preserves vanilla permissions and behavior. Permission level >=2 bypasses restrictions.
- Ordinary players gain self-only `/tp` and `/teleport` while restrictions are enabled. Vanilla admin command forms remain available to operators. Redirects are verified on the server. Client responses are revision-bound, time-limited and checked against the server result.
- Automatic roads are small deterministic segments, recomputed locally on block/state updates including removal and rail power. Server block changes also invalidate roads even with no client nearby. No scanner force-loads chunks. API-registered roads/stations have protection flags that automatic scans cannot remove.
- Portal activation updates road attachment and resolves existing Nether exits through vanilla portal lookup; actual portal travel confirms pairings (the far end may not exist before first use). End portals record the actual arrival platform/spawn. Links are persisted and invalidated on subsequent block changes.
- Safe landing checks happen server-side after graph resolution and cannot move the player outside the reachable area.

## Work packages and verification

1. **Build and metadata** — update template to an available compatible Loom/Gradle pairing, add bundled SQLite and JUnit, compile for Java 17.
2. **Graph model/geometry** (`graph/**`) — implement immutable validated records, segment/polygon intersection, segment proximity, transitive components and both modes. First add behavioral tests for disconnected overlapping cities, crossings, dimension isolation, station constraints and nearest-point projection.
3. **Road detection** (`detection/**`) — test and implement bounded block-reader rail/ice detectors; test straight routes, curves, inactive rails, width/guardrails and removal.
4. **Storage/config** (`storage/**`, `config/**`) — transactional SQLite snapshot round trips, per-world safe paths, validated configuration and protected data handling. Verify persistence including dimensions and protection flags.
5. **Fabric integration** — lifecycle, chunked/revisioned snapshot sync, client computation/response, server recomputation, authoritative changes, self-only command access, vanilla command interception, paired portals and API/admin city tooling.
6. **Review and delivery** — run `gradlew.bat test build`, inspect packaged metadata/nested dependencies, dedicated-server startup smoke test if available, document install/config/API and remaining in-game validation steps.

## Acceptance checks

- Level 2+ and console retain vanilla TP; ordinary players cannot target another entity.
- Unreachable destination dimension fails rather than leaking cross-dimension coordinate distance.
- A city boundary crossed by a road links even without an interior road vertex.
- Protected entries survive rescans, snapshots survive restart, and join sync replaces stale local data.
- Oversized/stale/forged client packets cannot mutate authoritative graph or teleport players.
- A server starts without loading client classes; mod jar contains SQLite dependency.
